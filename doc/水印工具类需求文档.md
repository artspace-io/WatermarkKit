# Swift 水印工具类需求文档

> 版本：v2（2026-09-14 修订）
> 修订说明见文末「附录 A：v1 → v2 变更记录」

## 一、模块定位

一个可同时用于「本地相册图片/视频加水印」与「AI 生成内容自动加水印」两类场景的 Swift 工具类。

**命名：`WatermarkKit`**（已定）。理由：Swift 有模块级命名空间，类型名无需再加 `ARK` 等前缀；且本模块定位为通用能力，挂具体 App 的域名前缀会限制跨项目复用。仓库与 podspec 均已采用该名称。

## 二、功能需求

### 1. 水印类型

- **文字水印**：文本、字体、颜色、描边、阴影、透明度、对齐方式、最大行数
- **图片水印**：支持带 alpha 通道的 PNG / `UIImage`
- **时间戳/来源标识水印**：语义限定为「**处理发生时刻**烧录的静态文本」（如 `2026-09-14 10:30`、`AI 生成`）。
  - ⚠️ 明确排除：视频播放过程中**逐帧递增**的时间码。该形态 `AVVideoCompositionCoreAnimationTool` 无法实现（Core Animation 不能逐帧替换文本内容），必须走逐帧渲染管线，归入后续版本的 `RenderStrategy` 扩展。

### 2. 布局与样式

- 九宫格预设位置 + 自定义坐标
- **所有几何量一律归一化（0...1 比例），不出现任何像素常量**——这是适配不同分辨率的唯一可靠手段，尺寸（`sizing`）同样按比例表达
- 缩放比例、旋转角度（统一使用**弧度**）、透明度、边距（margin，归一化）
- 平铺模式（可选，针对防盗用场景）：支持间距、倾斜角度、交错排列
- 支持多个水印同时叠加，**必须提供 `zIndex` 显式控制叠加顺序**（无确定顺序会产生难以复现的渲染差异）

### 3. 处理对象与输出

**图片**

- 输入：`UIImage`，或 `WatermarkSource`（见下文「输入抽象」）
- 输出：`UIImage` + 可选写入文件
- 支持格式：JPEG / PNG / HEIC
  - HEIC：A9 及更早设备、部分模拟器不支持硬件编码，**需自动降级为 JPEG** 并在结果中标记实际输出格式
- **元数据保留**（已定）：拆为两个独立开关
  - `preservesMetadata`，**默认 `true`** —— 保留 EXIF / TIFF / 拍摄时间等。加完水印照片日期丢失是典型用户投诉点
  - `preservesLocation`，**默认 `false`** —— GPS / 定位信息单独控制。加水印后的图片通常用于分享，默认剥离定位更稳妥；需要保留时由业务方显式开启
  - 两者关系：`preservesLocation` 仅在 `preservesMetadata == true` 时有意义；`preservesMetadata == false` 时一律不写任何元数据
  - 实现上不能使用 `UIImage.jpegData(compressionQuality:)`，必须走 `CGImageDestination` 手动拷贝 metadata 字典，并按开关剔除 `kCGImagePropertyGPSDictionary`
  - 必须正确处理 `UIImage.imageOrientation`，避免渲染后方向丢失
- **本期不支持**：Live Photo（降级为静态图输出）、HDR gain map 保留（iOS 18+ ISO HDR 照片加水印后可能变暗淡，需在实测后确认降级表现）

**视频**

- 输入：本地 `URL` / `AVAsset` / `PHAsset`（见下文「输入抽象」）
- 输出：处理后视频文件 `URL`
- 格式支持：mp4 / mov
- **横竖屏适配**：必须正确处理 `AVAssetTrack.preferredTransform`——
  - `layerInstruction` 设置 `setTransform(preferredTransform, at: .zero)`
  - `videoComposition.renderSize` 取 `naturalSize` 经 `preferredTransform` 变换后的 rect 尺寸
  - ⚠️ 水印 CALayer 的坐标系为**左下原点，且不随 layerInstruction 的 transform 旋转**，水印方位必须以最终显示方向为准换算
  - 这是本方案最主要的 bug 来源，需专门覆盖测试用例（0°/90°/180°/270° + 前置摄像头镜像素材）
- 保留原音轨（可配置）
- 分辨率、帧率跟随原视频：由 `videoComposition.renderSize` 与 `frameDuration = 1 / nominalFrameRate` 决定，**不依赖 export preset 的尺寸档位**
- 支持导出进度回调

### 4. 输入抽象（新增需求）

相册场景拿到的通常是 `PHAsset`，且资源**可能仅存于 iCloud、本地无实体文件**，需经 `PHImageManager.requestAVAsset` 异步下载（自带独立进度）。若接口只接受本地 `URL`，这段逻辑会被推给每个调用方重复实现。

```swift
public enum WatermarkSource {
    case url(URL)
    case asset(AVAsset)
    case phAsset(PHAsset)   // 由独立扩展 target 提供，核心库不强依赖 Photos
}
```

**已定：支持 `PHAsset`，拆为独立 subspec**

- `WatermarkKit/Core`：仅依赖 AVFoundation / UIKit / CoreImage，不含任何 Photos 符号
- `WatermarkKit/Photos`：提供 `PHAsset` 输入支持（`requestAVAsset` + iCloud 下载），依赖 `WatermarkKit/Core`
- 决策依据：纯 AI 生成场景（素材来自网络或本地生成，不触碰相册）不应被迫在 Info.plist 声明相册权限；相册场景也不必每个调用方重写一遍 iCloud 下载逻辑
- `WatermarkSource.phAsset` 这个 case 仅在引入 Photos subspec 时可用——需在实现时确定表达方式（条件编译 `#if canImport(Photos)`，或核心库只认 `AVAsset`、由 subspec 提供 `PHAsset -> AVAsset` 的异步适配层）。**推荐后者**，枚举里不出现跨 subspec 的 case，边界更干净
- iCloud 下载进度需并入总进度（建议分段：下载 0~30%，导出 30~100%）
- 需处理 iCloud 下载的特有错误：网络不可用、用户未开启「iCloud 照片」、资源已从设备移除

### 5. 视频导出质量策略

**采用质量预设方案，不做严格码率/编码格式对齐**，原因：

- 严格对齐原视频编码参数（codec、bitrate、profile level、色彩空间）实现成本高，涉及 HEVC/H.264 混合来源、HDR 视频时复杂度指数级上升
- `AVMutableVideoComposition` + `animationTool` 方案的导出阶段本身走 `AVAssetExportSession`，是预设驱动的，难以做到比特级对齐
- 业务方对码率精确对齐基本无感知，更关心清晰度、文件大小、导出速度

具体方案：

- `qualityPreset` 取值 **`.highest` / `.medium` / `.low`**，映射到对应的 `AVAssetExportPreset`
  - ⚠️ **本期不提供 `.custom(bitrate:)`**。`AVAssetExportSession` 无任何设置码率的 API，仅接受 preset；指定码率必须改用 `AVAssetWriter`。该能力与 AVAssetWriter 通道一并归入后续版本，避免开放一个实现不了的参数
- preset 选择依据源分辨率，优先使用 HEVC 预设（如 `AVAssetExportPresetHEVCHighestQuality`），而非笼统的 `AVAssetExportPresetHighestQuality`（后者可能对低分辨率素材**升采样**，导致文件变大而画质不变）
- **文件膨胀兜底（近似控制，非精确上限）**：
  - 读取源 `AVAssetTrack.estimatedDataRate`，若源码率明显低于目标 preset 的典型输出，自动降一档 preset
  - 导出前用 `AVAssetExportSession.estimatedOutputFileLength` 做磁盘空间粗筛
  - ⚠️ 表述不得写成「导出码率不超过原视频」——该保证在 `AVAssetExportSession` 上无法实现
- 后续如有精确码率控制需求（如商业交付场景），再针对性开放 `AVAssetWriter` 自定义通道作为进阶选项

## 三、技术实现方案

### 1. 视频水印渲染：CALayer 叠加为主

采用 `AVMutableVideoComposition` + `CALayer`（`AVVideoCompositionCoreAnimationTool`）方案，理由：

- **性能**：系统级合成，利用硬件加速，导出速度接近纯转码，长视频无内存爆炸风险
- **能力够用**：静态图片水印、文字水印、简单动画（透明度渐变、缓慢移动）均可覆盖
- **维护成本低**：无需自行管理 `CVPixelBuffer` / `Metal` 渲染管线

### 2. 该方案的已知约束（必须在实现中显式处理）

| 约束 | 说明 | 应对 |
| --- | --- | --- |
| 不支持实时播放 | `AVVideoCompositionCoreAnimationTool` 仅用于离线导出，不能用于 `AVPlayer` 预览 | 预览走另一条轻量路径（播放器上叠加原生 `UIView`），不复用导出管线 |
| 动画时间基准特殊 | CALayer 动画须设 `beginTime = AVCoreAnimationBeginTimeAtZero`（不可为 0）、`isRemovedOnCompletion = false`、`speed = 1` | 封装在内部，不暴露给业务方 |
| 后台渲染挂起 | 依赖 Core Animation，App 切后台时渲染可能挂起，导致导出卡死或黑帧 | 见「后台导出策略：`.suspendAndResume`」 |
| HDR 降级 | HDR 素材经 animationTool 大概率被 tone-map 成 SDR，用户可直接看出画面变灰 | 见「HDR 策略：`.downgradeToSDR`」 |
| 逐帧内容变化不可行 | 无法按帧替换文本/图像内容 | 归入后续版本的逐帧渲染策略 |

**后台导出策略：`.suspendAndResume`（已定）**

- 切入后台时暂停导出，申请 `beginBackgroundTask` 争取缓冲时间；回到前台后从暂停点继续
- 后台时间耗尽仍未回前台，以 `.interrupted` 结束并清理临时文件
- 决策依据：「AI 生成完自动串联」场景下用户极可能在生成后立即切走，直接失败会导致整批白跑
- 实现注意：需处理暂停点的状态一致性——`AVAssetExportSession` 本身不支持真正的暂停续跑，实际做法是 `cancelExport()` 后记录已完成进度，回前台重新发起导出。因此「续跑」在当前方案下等价于「重跑」，需评估长视频场景下的体验；若重跑成本不可接受，再考虑迁移到 `AVAssetWriter` 通道实现真正的分段续写
- `VideoOutputConfig.backgroundPolicy` 字段保留，默认 `.suspendAndResume`

**HDR 策略：`.downgradeToSDR`（已定）**

- 检测到 HDR 素材时正常加水印导出，**静默降级为 SDR**
- 结果结构体中标记 `didDowngradeHDR = true`，由业务方决定是否提示用户
- 决策依据：优先保证「水印一定加上」，画质损失可感知但可接受；跳过水印会造成版权/来源标识漏网
- ⚠️ 实际 tone-map 表现必须在目标系统版本上实测确认，可能比预期差。若实测发现画面劣化严重，需回头评估是否对 HDR 素材改走 `AVAssetWriter` 通道保真处理

### 3. 扩展口子

API 协议化，预留 `RenderStrategy` 接口，以后如需逐帧渲染（Core Image / Metal，用于逐帧递增时间码、像素级分析、动态跟踪、复杂滤镜混合等场景）可平滑扩展，不用推倒重来。

```swift
public protocol RenderStrategy: Sendable {
    /// 返回可直接交给 AVAssetExportSession / AVAssetWriter 的合成描述
    func makeComposition(for asset: AVAsset, config: WatermarkConfig) async throws -> CompositionPlan
}
```

本期仅实现 `CoreAnimationRenderStrategy`；`PerFrameRenderStrategy`（AVAssetWriter + Core Image）为后续版本。

## 四、配置模型 `WatermarkConfig`

拆为三层而非单一扁平 struct——「多水印叠加」需求决定了必须是「item 数组 + 全局导出配置」的结构。

```swift
public struct WatermarkConfig: Sendable {
    public var items: [WatermarkItem]          // 支持多水印叠加
    public var output: OutputConfig            // 图片/视频共用的导出配置
    public var video: VideoOutputConfig        // 视频专有
}

public struct WatermarkItem: Sendable {
    public var content: Content
    public var layout: Layout
    public var style: Style
}

public enum Content: Sendable {
    case text(String, attributes: TextAttributes)
    case image(UIImage)
}

public struct TextAttributes: Sendable {
    public var font: UIFont
    public var color: UIColor
    public var strokeColor: UIColor?
    public var strokeWidth: CGFloat            // 沿用 NSAttributedString 语义：负值 = 描边 + 填充
    public var shadow: NSShadow?
    public var alignment: NSTextAlignment
    public var lineBreakMode: NSLineBreakMode
    public var maxLines: Int
}

public struct Layout: Sendable {
    public enum Anchor: Sendable {
        case preset(Position)                  // 九宫格
        case relative(CGPoint)                 // 归一化坐标 0...1
    }
    public var anchor: Anchor
    public var margin: RelativeInsets          // 归一化，非像素
    public var sizing: Sizing                  // .relativeWidth(0.2) / .relativeHeight(_) / .fixedScale(_)
    public var rotation: CGFloat               // 弧度
    public var tiling: Tiling?                 // nil = 不平铺；含 spacing / angle / staggered
    public var zIndex: Int                     // 多水印叠加顺序，必填
}

public struct Style: Sendable {
    public var opacity: CGFloat                // 0...1
    public var blendMode: CGBlendMode
}

public struct OutputConfig: Sendable {
    public var imageFormat: ImageFormat        // .jpeg(quality:) / .png / .heic(quality:)
    public var preservesMetadata: Bool         // EXIF / TIFF / 拍摄时间，默认 true
    public var preservesLocation: Bool         // GPS 定位，默认 false（隐私考量，单独开关）
    public var destination: Destination        // .memoryOnly / .file(URL) / .temporary
}

public struct VideoOutputConfig: Sendable {
    public var qualityPreset: QualityPreset    // .highest / .medium / .low
    public var fileType: AVFileType            // .mp4 / .mov
    public var preservesAudio: Bool            // 默认 true
    public var hdrPolicy: HDRPolicy            // .downgradeToSDR / .skipWatermark
    public var backgroundPolicy: BackgroundPolicy  // .suspendAndResume / .failFast
}
```

设计约定：

- 全部类型标注 `Sendable`，保证可安全跨 actor 传递
- 几何量一律归一化，旋转统一弧度
- 提供静态便利构造覆盖约 80% 调用场景，避免业务方每次填十余个字段：
  - `WatermarkConfig.bottomRightLogo(_:)`
  - `WatermarkConfig.tiledText(_:)`

## 五、接口设计

统一封装，核心用 `async throws` 实现，外层再包 Combine `Publisher` 和 completion handler 便利 API。

按职责拆分协议，避免图片实现被迫承担视频逻辑：

```swift
public protocol ImageWatermarkRendering: Sendable {
    func applyWatermark(
        to image: UIImage,
        config: WatermarkConfig
    ) async throws -> ImageWatermarkResult
}

public protocol VideoWatermarkRendering: Sendable {
    func applyWatermark(
        to source: WatermarkSource,
        config: WatermarkConfig
    ) async throws -> VideoWatermarkResult

    /// 进度以 AsyncStream 暴露，天然支持取消，且规避逃逸闭包的 Sendable 约束
    func applyWatermark(
        to source: WatermarkSource,
        config: WatermarkConfig,
        progress: AsyncStream<Double>.Continuation?
    ) async throws -> VideoWatermarkResult
}
```

- 返回值用 `Result` 结构体而非裸 `UIImage` / `URL`，以便携带 `actualFormat`（HEIC 降级结果）、`didDowngradeHDR` 等实际处理信息
- 便利层：Combine `Publisher` + completion handler（内部统一调用 async 版本），兼容 UIKit / Combine 混用场景
- 支持 `Task` 取消（视频导出耗时长，用户中途退出页面时需能取消）；**取消后必须清理已产生的临时文件**

**输出文件生命周期**（新增约定）：

- 默认写入 `NSTemporaryDirectory()` 下带 UUID 的独立子目录
- 失败 / 取消时由 Kit 负责清理半成品；成功后文件所有权移交调用方
- 额外提供 `cleanupTemporaryFiles()` 供业务方兜底清理（视频文件体积大，漏删会直接占用用户存储空间）

## 六、批量处理与并发

图片与视频必须采用不同并发策略，不可共用同一上限。

**视频：并发数固定为 1（串行）**

- 视频编码走硬件编码器，属全局独占资源；并发多个 `AVAssetExportSession` 无吞吐收益，反而互相抢占拖慢整体，4K 素材下易 OOM
- 系统对同时存在的 export session 数量本身亦有限制
- 总进度 = 已完成数 / 总数 + 当前任务内部进度

**图片：`min(4, ProcessInfo.processInfo.activeProcessorCount)`**

- 以 `TaskGroup` 控制在途任务数
- 上限取 4 的依据是内存峰值而非 CPU——每张解码后 bitmap 可能达数十 MB，无节制并发会被 jetsam 终止
- 源图长边 > 4000px 时进一步降至 2

**队列语义**

- 支持整体取消与单任务取消，取消后清理所有已产出临时文件
- 失败策略：默认**跳过失败项继续执行**，返回 `[Result<Output, WatermarkError>]` 而非 `[Output]`，由业务方决定重试或提示

## 七、错误处理

```swift
public enum WatermarkError: Error, Sendable {
    case fileNotFound(URL)
    case unsupportedFormat(String)
    case noVideoTrack              // 纯音频文件
    case assetNotReadable          // DRM 保护等
    case iCloudDownloadFailed(underlying: Error)
    case invalidWatermarkImage
    case outputPathNotWritable(URL)
    case exportFailed(underlying: Error)
    case diskFull
    case interrupted               // 来电、长时间后台等系统中断
    case cancelled
}
```

约定：

- **`diskFull` 不做事前精确检查**（拿不准且存在 TOCTOU 问题），而是将 `AVError.diskFull` 事后映射过来；事前仅用 `estimatedOutputFileLength` 做粗筛提示
- 所有错误须携带足以定位的上下文（源 URL、底层 `Error`），便于线上问题排查

## 八、场景适配

**相册场景**

- 直接处理用户选中的图片/视频
- 输入可能为 `PHAsset` 且资源在 iCloud，需支持异步下载并合并进度
- 元数据保留（EXIF / GPS / 拍摄时间）对该场景尤为重要——用户加完水印发现照片日期丢失是典型投诉点

**AI 生成内容场景**

- 需在生成完成后自动串联执行，设计成可插入现有生成 pipeline 的独立 step
- 支持批量处理，并发策略见第六节
- 后台导出策略对该场景影响最大（用户极可能生成后立即切出 App）
- 「AI 生成」来源标识按普通文字水印处理；元数据隐式标识本期不做（见第十节「非目标」）

## 九、工程约束

- **最低系统版本：iOS 16.0**（已定）
  - v1 文档与 podspec 中的 `10.0` 与接口设计冲突：`async/await` 最低回溯至 iOS 13，Combine 亦为 iOS 13 起，直接无法编译
  - 选 16.0 而非 13/15 的直接理由：`AVAsset.load(_:)` 等 async 属性加载 API 自 iOS 16 起提供；低于该版本只能使用已废弃的同步属性访问（`asset.tracks`、`track.naturalSize` 等），在 Swift 6 严格并发下会持续产生告警且无干净写法
  - `WatermarkKit.podspec` 的 `s.ios.deployment_target` 已同步为 `16.0`
- **Swift 版本**：Swift 5.9+，按 Swift 6 严格并发模式要求编写（全链路 `Sendable`）
- **依赖**：核心库仅 AVFoundation / UIKit / CoreImage；Photos 通过独立 subspec 引入

**性能验收指标**（新增，用于判定实现是否达标）：

| 场景 | 指标 |
| --- | --- |
| 1080p / 60s 视频，iPhone 13 | 导出耗时 ≤ 15s，峰值内存 ≤ 200MB |
| 4K / 60s 视频，iPhone 13 | 导出耗时 ≤ 60s，峰值内存 ≤ 400MB |
| 4000×3000 单图 | 处理耗时 ≤ 300ms，峰值内存 ≤ 150MB |
| 批量 50 张图片 | 全程无内存告警，无 jetsam |

**测试要求**：

- 视频方向必须覆盖 0° / 90° / 180° / 270° 及前置摄像头镜像素材
- 图片需覆盖全部 8 种 `UIImage.Orientation`
- 元数据保留需有断言校验（EXIF / GPS 字段在处理前后一致）

## 十、非目标（明确排除，归入后续版本）

- 精确码率控制与 `AVAssetWriter` 自定义导出通道
- 逐帧渲染策略（逐帧递增时间码、像素级分析、动态跟踪、复杂滤镜混合）
- Live Photo 加水印（本期降级为静态图）
- HDR 保真输出（本期降级 SDR）
- 实时播放预览复用导出管线（预览走独立轻量路径）
- **AIGC 元数据隐式标识**（生成合成属性、服务提供者名称/编码、内容编号）——本期仅提供画面可见的文字/图片水印（显式标识），元数据写入待合规要求与业务口径明确后再评估
- 视频音轨处理（混音、消音以外的能力）

## 附录 A：v1 → v2 变更记录

**修正的技术性错误**

1. 移除 `.custom(bitrate:)`——`AVAssetExportSession` 无码率设置 API，与 v1 自述的「预设驱动」相矛盾
2. 修正「导出码率不超过原视频」的兜底描述——该保证在所选方案下无法实现，改为基于 `estimatedDataRate` 的降档近似控制
3. 明确分辨率/帧率由 `renderSize` + `frameDuration` 决定，而非 export preset；避免 `HighestQuality` 对低分辨率素材升采样
4. 限定「动态文本水印」语义为静态烧录时间戳；逐帧递增时间码在 CALayer 方案下不可行，移入非目标
5. 最低系统版本由 10.0 提升至 **16.0**——原值与 `async/await`、Combine 冲突无法编译；定 16.0 是为使用 `AVAsset.load(_:)` 等 async 属性加载 API

10. 后台导出策略
11. HDR 素材降级策略

## 附录 B：v2 评审决策记录（2026-09-14）

| 议题 | 决策 | 依据 |
| --- | --- | --- |
| 最低系统版本 | **iOS 16.0** | 需要 `AVAsset.load(_:)` 等 async 属性加载 API；podspec 已同步 |
